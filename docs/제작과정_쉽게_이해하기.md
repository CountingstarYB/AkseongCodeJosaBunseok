# 🛡️ 코딩을 몰라도 이해하는 "내 업무 도구 만들기"부터 "인터넷 배포"까지

> 💡 **이 글은 이런 분을 위해 썼습니다**
> 코딩을 배운 적이 없지만, "업무에 쓰는 도구를 직접 만들어 인터넷에 올리는 과정"이 어떻게 돌아가는지 궁금한 분.
> 실제 사례인 **「악성코드 조사분석 보고서 에이전트」** 를 만든 과정을 처음부터 끝까지 따라갑니다.

## 1단계. 기획 — "무엇이 불편한가?"를 글로 쓰기

### 왜 필요한가요?
AI는 시키는 대로 잘 만들지만, **무엇을 원하는지 모르면 엉뚱한 것을 만듭니다.** 그래서 먼저 "누가, 어떤 상황에서, 무엇이 불편한지"를 정리합니다.

### 실제로 정리한 불편함
1. 백신이 업데이트되면 **2~3년 전부터 있던 파일이 갑자기 악성으로 탐지**됩니다. 이걸 설명하는 문장을 매번 손으로 씁니다.
2. 보고서에 **"그 외 악성행위는 없다"** 를 써야 하는데, 무엇을 확인했는지 남기지 않으면 근거가 없습니다.
3. **비슷한 과거 사례**를 찾으려면 문서를 하나씩 열어 봐야 합니다.

### 결과물: 요구사항 문서(PRD)
이 내용을 **PRD**라는 문서로 정리했습니다.

> 📖 **PRD (Product Requirements Document)**
> "이 프로그램은 이런 기능이 있어야 한다"를 적은 **설계도**입니다. 어려운 형식이 필요 없고, 평소 말투로 써도 됩니다.

## 2단계. 제작 — AI에게 "이대로 만들어 줘"

### 사용한 도구: Claude Code
**Claude Code**는 대화하듯 말하면 직접 코드를 써 주는 AI 도구입니다.
실제로 입력한 첫 문장은 이것뿐이었습니다.

> 💬 "PRD 문서 이대로 개발 시작해"

AI가 설계도를 읽고 프로그램을 만들었고, 사람은 **결과를 보고 "여기는 이렇게 바꿔 줘"라고 말하는 역할**을 했습니다.

### 어떤 형태로 만들었나요?
**HTML 파일 하나**로 만들었습니다.

> 📖 **HTML 파일**
> 인터넷 브라우저(크롬 등)로 여는 문서입니다. 더블클릭하면 웹사이트처럼 열립니다.

이렇게 만든 이유는 **실제로 쓸 곳이 인터넷이 막힌 폐쇄망**이기 때문입니다. 설치 없이 파일 하나만 복사하면 어디서든 열립니다.

### 데이터는 어디에 저장되나요?
**그 PC의 브라우저 안**에 저장됩니다. 어떤 서버로도 보내지 않습니다.

> 🔒 군 업무 자료를 다루므로 **"밖으로 아무것도 나가지 않는다"** 를 가장 중요한 원칙으로 삼았습니다.

## 3단계. 꾸미기 — 쓰고 싶은 도구로 만들기

기능이 돌아간 뒤, 말로 요청해서 하나씩 바꿨습니다.

- 이름을 "보고서 **도우미**" → "보고서 **에이전트**"로 변경
- 모든 화면에 부대 로고, 맨 아래에 공군 마크·슬로건
- **로그인 화면** 추가 (체험용 계정 admin / admin)
- 로그인 화면 왼쪽에 공군 마크와 사이버 느낌을 섞은 배경 그림
- 전체 색을 **#243259**(남색)으로 통일
- 어두운 곳에서 쓰기 위한 **다크 모드** 버튼
- 로그인 없이 바로 둘러보는 **체험하기** 버튼

> ✅ **팁**: 처음부터 완벽하게 말할 필요 없습니다. 만들어진 걸 보고 "로고가 안 보여", "동그란 틀이 어색해"처럼 **느낀 대로 말하면** 고쳐 줍니다.

## 4단계. 보관 — GitHub에 올리기

### GitHub이 뭔가요?
> 📖 **GitHub**
> 코드를 보관하는 **인터넷 창고**입니다. 언제 무엇을 바꿨는지 기록이 모두 남아서, 잘못되면 예전으로 되돌릴 수 있습니다.

### 용어 3개만 알면 됩니다

| 용어 | 뜻 | 비유 |
|---|---|---|
| 저장소 (Repository) | 프로젝트 하나를 담는 창고 | 창고 한 칸 |
| 커밋 (Commit) | "여기까지 바꿨음"을 기록 | 작업 일지 한 줄 |
| 푸시 (Push) | 내 PC의 기록을 GitHub에 올림 | 창고로 택배 보내기 |

### 실제로 한 일
1. GitHub에 저장소를 만들었습니다.
2. AI가 PC에 Git(올리는 프로그램)을 설치하고 코드를 올렸습니다.
3. 처음 한 번만 **GitHub 로그인은 직접** 했습니다.
4. 그 뒤로는 무언가 바뀔 때마다 AI가 **바로 커밋·푸시**했습니다.

### ⚠️ 절대 올리면 안 되는 것
**`.gitignore`** 라는 파일에 "이건 올리지 마"라고 적어 두었습니다.
- 사례 백업 파일 (PC 이름, 부서명, 내부 IP 같은 민감 정보가 들어갈 수 있음)
- `.env.local` (데이터베이스 연결 정보, 7단계에서 설명)

## 5단계. 배포 — Vercel로 인터넷 주소 만들기

### 배포가 뭔가요?
> 📖 **배포**
> 내 PC에만 있던 프로그램을 **누구나 주소로 접속할 수 있게** 인터넷에 올리는 것입니다.

### Vercel이 뭔가요?
> 📖 **Vercel**
> GitHub 창고에 있는 코드를 가져가서 **웹사이트로 만들어 주는 서비스**입니다. 개인 비상업 용도는 무료입니다.

### 실제 순서
1. Vercel에 **GitHub 계정으로 로그인** (직접)
2. Vercel이 GitHub 창고를 볼 수 있게 **권한 허용** (직접)
3. 저장소 선택 → 설정은 **Other**(특별한 프레임워크 없음) → **Deploy** 클릭 (AI)
4. 이메일로 온 **인증 코드 입력** (직접)
5. 약 2초 만에 완료 → 주소 발급

> 🌐 **결과**: https://akseongcodejosabunseok.vercel.app
> 주소 끝에 **`?demo`** 를 붙이면 로그인 없이 바로 체험 화면이 열립니다.

### 이게 제일 좋은 점
한 번 연결해 두면 **GitHub에 새로 올릴 때마다 Vercel이 알아서 다시 배포**합니다. 고치고 → 올리고 → 1~2분 뒤 사이트에 반영됩니다.

> 🙋 **왜 로그인·권한 허용·인증 코드는 직접 했나요?**
> 비밀번호 입력, 계정 권한 허용, 인증 코드 입력은 **본인 확인 절차**라서 AI가 대신하지 않습니다. 사람이 그 부분만 처리하면 나머지는 AI가 이어서 진행합니다.

## 6단계. 데이터베이스 — Supabase에 금고 만들기

### 데이터베이스가 뭔가요?
> 📖 **데이터베이스 (DB)**
> 데이터를 **엑셀 표처럼** 저장하는 곳입니다. 여러 사람이 같은 데이터를 함께 쓰려면 필요합니다.

> 📖 **Supabase**
> 인터넷에 데이터베이스를 쉽게 만들어 주는 서비스입니다.

### 실제로 만든 것: `cases` 표
사례 하나가 표의 **한 줄**이 되도록 만들었습니다. (제목, 사건번호, 분석일, 판정, 해시값, 사례 전체 내용 등)

### 🔐 가장 중요한 것: 보안 설정 3종
표만 만들면 **누구나 데이터를 보고 지울 수 있는 상태**가 될 수 있습니다. 그래서 잠금장치를 달았습니다.

| 설정 | 하는 일 | 비유 |
|---|---|---|
| **RLS** (행 단위 보안) | 표의 각 줄마다 "누가 볼 수 있는지" 검사 | 금고 칸마다 **이름표 자물쇠** |
| **정책 (Policy)** | "자기가 만든 사례만 보고·쓰고·지울 수 있다" 규칙 | 자물쇠의 **열쇠 규칙** |
| **GRANT** (권한) | 로그인 안 한 사람은 아예 접근 금지 | 금고실 **출입문** 잠그기 |

### 실제로 겪은 일
설정을 적용한 뒤 확인해 보니, Supabase가 기본으로 **"표 전체 비우기(TRUNCATE)" 권한**까지 열어 두고 있었습니다. 이 권한은 자물쇠(RLS)를 무시하기 때문에 바로 회수했습니다.

> ✅ **교훈**: 설정하고 끝내지 말고 **"정말 막혔는지" 직접 시험**해 봐야 합니다. 로그인 없이 읽기·쓰기를 시도해 **둘 다 거부되는 것**까지 확인했습니다.

> 📝 지금 앱은 아직 이 데이터베이스를 쓰지 않습니다. 나중에 여러 사람이 사례를 함께 보도록 바꿀 때를 위해 **금고를 미리 설치**해 둔 단계입니다.

## 7단계. 연결 정보 — 환경변수와 Redeploy

### 환경변수가 뭔가요?
> 📖 **환경변수**
> 프로그램이 데이터베이스를 찾아가는 데 필요한 **주소와 열쇠**입니다. 코드 안에 직접 쓰지 않고 따로 보관합니다.

사용한 값은 2개입니다.
- `NEXT_PUBLIC_SUPABASE_URL` — 금고 **주소**
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — 금고 **공개용 열쇠**

### 두 군데에 따로 넣어야 합니다

| 위치 | 용도 |
|---|---|
| 내 PC의 `.env.local` 파일 | 내 PC에서 실행할 때 사용 (GitHub에는 **안 올라감**) |
| Vercel 설정 화면 | 인터넷 사이트에서 사용 |

> ❓ **왜 두 번 넣나요?**
> `.env.local`은 GitHub에 올리지 않게 막아 뒀기 때문에, Vercel은 이 값을 모릅니다. 그래서 Vercel에도 **따로 알려 줘야** 합니다.

### Redeploy는 왜 하나요?
환경변수는 **배포할 때 사이트에 들어갑니다.** 그래서 저장만 하면 이미 만들어진 사이트에는 반영되지 않습니다.

> 🍳 **비유**: 환경변수 저장은 **레시피에 재료를 추가**하는 것이고, Redeploy는 그 레시피로 **요리를 새로 만드는** 것입니다. 레시피만 고치면 이미 나간 요리는 그대로입니다.

**순서**: Vercel → Settings → Environment Variables에 저장 → Deployments → 최신 배포의 **⋯ → Redeploy**

### ⚠️ `NEXT_PUBLIC_` 이 붙은 이름의 의미
이 이름이 붙은 값은 **사이트를 여는 누구나 볼 수 있습니다.**
- 공개용 열쇠(publishable key) → 붙여도 됨 (그래서 6단계 잠금장치가 꼭 필요)
- **비밀 열쇠(secret key), AI API 키 → 절대 붙이면 안 됨**

## 8단계. 최종 점검 — 준공 검사

| 점검 항목 | 결과 |
|---|---|
| 코드가 내 GitHub 저장소에 있다 | ✅ |
| `.env.local`이 GitHub에 올라가지 않았다 | ✅ (직접 주소로 열어 봐도 404) |
| Supabase 표에 RLS·정책·GRANT 적용 | ✅ (로그인 없이 읽기·쓰기 모두 거부 확인) |
| Vercel 환경변수 이름이 정확하다 | ✅ (대소문자까지 동일) |
| 비밀 키에 `NEXT_PUBLIC_`이 없다 | ✅ (저장소 전체 검사) |
| 환경변수 저장 후 Redeploy 했다 | ✅ |
| Site URL / Redirect URLs 설정 | ➖ (Supabase 로그인을 안 쓰므로 해당 없음) |
| 휴대폰에서 입력·저장·로그인 | ✅ (점검 중 **로고가 잘리는 문제를 발견해 수정**) |
| 입력한 데이터가 모두 가상 데이터다 | ✅ |

> ✅ **교훈**: 큰 화면에서 멀쩡해도 **휴대폰에서는 깨질 수 있습니다.** 실제로 휴대폰 로그인 화면에서 로고 윗부분이 잘려 있었고, 점검 덕분에 고쳤습니다.

## 9단계. 발표 준비 — 갤러리 등록

- **작품 설명**: 해결하려는 문제, 주요 기능, 현장 활용 시나리오, 사용 도구, 후기
- **썸네일**: 다른 작품들처럼 큰 제목 + 실제 화면을 겹친 포스터형 이미지
- **화면 콜라주**: 로그인 → 목록 → 입력 → 보고서 화면 4장을 한 장으로
- **배포 주소**: `?demo`를 붙여서, 심사하는 AI가 로그인 화면이 아니라 **실제 기능 화면**을 보게 함

## 🎯 정리 — 사람이 한 일 vs AI가 한 일

| 사람이 한 일 | AI가 한 일 |
|---|---|
| 무엇이 불편한지 정리 | 코드 작성 |
| 결과를 보고 "이렇게 바꿔 줘" | 디자인·기능 수정 |
| 로그인·권한 허용·인증 코드 입력 | GitHub 업로드, Vercel 배포 클릭 |
| 비밀 열쇠 입력 | 데이터베이스 표·보안 설정 SQL 작성·실행 |
| 휴대폰으로 최종 확인 | 점검, 문제 발견·수정, 썸네일 제작 |

> 💬 **한 줄 요약**
> 코딩을 몰라도 **"무엇이 불편한지"를 가장 잘 아는 사람**이 AI와 대화하며 직접 업무 도구를 만들고, 인터넷에 올릴 수 있습니다.
