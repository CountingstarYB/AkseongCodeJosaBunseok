## 해결하려는 문제

악성코드 조사분석 보고서를 쓸 때마다 같은 세 가지 벽에 부딪힙니다.

1. **"왜 예전부터 있던 파일이 이제 악성이냐"를 설명하기 어렵습니다.** 백신 패턴이 업데이트되면 2~3년 전부터 PC에 있던 파일이 갑자기 탐지됩니다. 로그는 이미 지워졌고, 생성일·탐지일·패턴 버전을 맞춰 설명 문장을 매번 손으로 씁니다.
2. **"그 외 악성행위는 없다"를 입증하기 어렵습니다.** 광고 팝업처럼 드러난 행위는 쓰기 쉽지만, 정보 탈취·전파·지속성 같은 나머지 행위가 없다는 것은 무엇을 확인했는지 남기지 않으면 근거가 되지 않습니다. 내부망에는 샌드박스 보고서도 없습니다.
3. **비슷한 사례를 찾는 데 시간이 오래 걸립니다.** 10년 치 분석 목록이 있지만, 같은 해시·도메인·행위를 본 적이 있는지 문서를 하나씩 열어 봐야 합니다.

이 도구는 사례를 정해진 항목으로 기록하면 ① 패턴 업데이트 설명 문장, ② 23개 행위를 하나하나 점검한 결과로 만든 "확인됨 / 확인되지 않음 / 확인 불가(사유)" 문장, ③ 해시·도메인·행위 기준 유사 사례를 자동으로 만들어 줍니다. 기존 보고서 양식(HWP)을 대체하지 않고, 양식에 바로 붙여 넣을 문안만 만듭니다.

## 현장 활용 시나리오

조사분석 담당 분석관 A에게 "PC에서 광고 프로그램이 탐지됐다"는 건이 접수됩니다.

1. **[새 사례]** 를 누르고 파일명·해시·탐지명, 생성일(2024.03.12.)·최초 탐지일(2026.10.30.)·패턴 버전을 입력합니다.
2. 유입경위에 "번들 설치"와 근거를 적고, 웹 로그가 없어 확인 못 한 부분은 **확인 불가 사유**로 남깁니다.
3. **악성행위 체크리스트 23개**(MITRE ATT&CK 번호 표시)를 위에서부터 "확인됨 / 없음 확인 / 확인 불가"로 채웁니다.
4. **[유사 사례 찾기]** 를 누르면 과거 사례가 순위와 함께 "공통 행위 2개: 번들 설치, …" 같은 **근거**로 표시됩니다. 눌러서 과거 분석 내용을 참고합니다.
5. **[보고서 문안 보기]** 에서 1페이지(개요·유입·탐지·악성행위·피해·조치)와 세부내용(개요도·진행과정·침해지표·악성코드)을 섹션별로 복사해 기존 HWP 양식에 붙여 넣습니다. 비어 있는 항목은 `[미입력: …]` 으로 강조돼 누락을 막습니다.
6. 사례는 자동 저장되어 다음 사례 검색 대상이 되고, JSON 백업으로 부서원과 공유합니다.

→ 매번 손으로 쓰던 설명 문장과 "그 외 행위 없음" 근거가 체크 한 번으로 만들어지고, 과거 사례 검색이 버튼 하나로 끝납니다.

## 사용한 도구·기술

Claude Code(바이브코딩), HTML/CSS/JavaScript 단일 파일(외부 라이브러리·CDN 없음), 브라우저 저장소(localStorage), MITRE ATT&CK 기법 번호 매핑, Python(Pillow, 로고 처리), GitHub, Vercel

## 보안 설계

- **서버 전송 0건**: 입력한 내용은 그 PC의 브라우저에만 저장되고 어떤 서버로도 전송되지 않습니다. 페이지 자체에 외부 연결을 막는 보안 정책(CSP)을 걸었습니다.
- **폐쇄망 그대로 사용**: HTML 파일 하나를 복사해 열면 설치·인터넷 없이 동작합니다.
- **가상 데이터만 공개**: 공개 시연 사이트에는 공개 분석 자료로 재구성한 가상 사례 5건만 들어 있고, 실제 정보 입력 금지 안내를 상단에 표시합니다. 존재하지 않는 주소(.example 도메인, 문서용 IP 대역)로 침해지표를 만들고 무력화 표기(hxxp, [.])로 보여 줍니다.
- **체험용 계정**: admin/admin은 가상 데이터 시연 전용이며, 실제 운영 시 국방망 통합 인증으로 교체합니다.

## 제작 후기

처음에는 "보고서 문장을 대신 써 주는 도구"를 생각했지만, 만들면서 가장 어려운 것은 문장이 아니라 **"없다는 것"을 입증하는 일**이라는 걸 알게 됐습니다. 그래서 행위를 23개로 세분화하고, 각각 "없음 확인"인지 "확인 불가"인지 구분해 기록하게 했습니다. 확인하지 못한 것을 생략하지 않고 사유와 함께 남기는 것이 보고서의 신뢰를 지킨다고 판단했습니다. 행위 태그에는 MITRE ATT&CK 기법 번호를 붙여 외부 보고서와 같은 기준으로 말할 수 있게 했습니다.

AI 자동 분석은 일부러 넣지 않았습니다. 실제 사용 환경이 인터넷이 막힌 폐쇄망이고, 분석 판단은 분석관이 하되 반복되는 문장 작성과 검색을 줄이는 것이 현장에 더 필요했기 때문입니다.

다음 단계는 10년 치 과거 분석 목록을 CSV로 한 번에 가져와 유사 사례 검색의 실효성을 높이는 것, 그리고 내부 규정이 확정되면 민감 정보 마스킹과 백업 파일 암호화를 넣는 것입니다.
